# 可答性判断评测（M3 A1）

**日期**：2026-10-13
**数据**：M1 的 T2Ranking 运行记录（300 query × 3 方案），不重跑检索
**数据表**：[answerability_tables.md](answerability_tables.md)（脚本生成）
**复现**：`python scripts/eval_answerability.py --out docs/eval/answerability_tables.md`

## 结论

1. **M1 的"单一阈值不可行"下得过重，19.1% 不是单阈值的能力上限。**
   M1 以 0.05 为步长扫描，恰好跨过拐点：阈值 0.75 → 识别率 19.1%、误拒 3.0%；
   0.80 → 79.9%、19.0%。细网格下单阈值在 0.78 附近，交叉验证识别率
   **58.9%** [53.2, 64.3]，误拒 10.0%。准确的说法是：**单阈值可用但极脆弱**
   —— 阈值每动 0.01，识别率变化约 12 个百分点。

2. **计划中的 top1−top2 分差规则（R1）没有用，否决。**
   5 折里每一折都把分差阈值选成 0（等于关掉这个条件）；相对单阈值的
   配对差 −1.3 [−2.7, −0.3]。原因：每条 query 平均有 5 条 gold，
   有答案时 top1 与 top2 往往都是 gold、分数相近，分差反而小。

3. **"top1 比背景高出多少"（R2 `gap_bg`）有效，但只在看得到候选池时有效。**
   - 可见 top-20：识别率 **70.6%** [65.3, 75.8]，误拒 10.7%，
     相对单阈值 **+11.7** [+5.7, +18.3] 个百分点
   - 可见 top-3（生产当前）：识别率 12.0%，背景分只由 2 条算出，失效
   - 5 折的阈值都在 0.031–0.034 之间，稳定

   验证了各向异性假设：bge 余弦的绝对值挤在窄区间，相对值才携带信息。

4. **在可答性上，余弦 `gap_bg`（约 50ms）与 rerank 单阈值（P50 9.8 秒）统计上无差别。**
   同一批 300 条 query 配对比较：识别率差 [−7.4, +5.3]，误拒率差 [−2.3, +5.0]，
   两个区间都跨过 0。**可答性判断不需要 rerank**；rerank 的价值在排序质量
   （MRR@10 0.947 vs 0.902），A2 应据此评估，而不是为了可答性开启它。

5. **rerank 分数被 sigmoid 了两次**（已修复，`4d933b8`）。修复前开启 rerank 时，
   relevance 恒 ≤ 0.731，低于 0.75 阈值，**所有查询都被判为不可答**。
   修复后同一个 0.75 阈值在 rerank 口径下识别率 67.6%、误拒 9.3%；
   该口径的交叉验证最优阈值为 0.79。

## 必须同时看到的两个限制

**单 gold 查询的误拒率在 26%–35%。** 总体误拒率 10% 是多 gold 查询拉低的：

| top-20 中 gold 数 | query 数 | 单阈值 误拒 | `gap_bg` 误拒 |
|---|---|---|---|
| 1 | 35 | 34.3% | 28.6% |
| 2–4 | 122 | 5.7% | 4.9% |
| ≥5 | 133 | 0.8% | 6.8% |

真实知识库里一个问题往往只有一个相关 chunk，**线上误拒率很可能显著高于
10%**。只有一条相关证据时，它在分数上不突出，任何只看检索分数的规则都难以
区分"证据少"与"没证据"。这是 A3（灰区 LLM 校验）的主要动机。

**无答案集是合成的。** 剔除 gold 后剩下的是随机干扰段落；真实场景的无答案
查询，残留文档往往与问题同主题、更难区分。识别率可能高估线上表现。

另外，交叉验证的留出误拒率是 10.0%–12.0%，略高于选参时的 10% 约束 ——
样本外漂移。上线选阈值时应留余量（例如按 8% 约束选）。

## 对后续任务的影响

| 任务 | 变化 |
|---|---|
| **A4 生产接入** | 余弦口径用 `gap_bg`，**需要把候选池分数传给判断函数**（`retrieve_advanced` 随 `stats` 传出），不能只看最终 3 条。过渡方案：不改接口时用 `top1 ≥ 0.78`（top-3 下交叉验证 57.2% / 10.7%）。rerank 口径用独立阈值 ≈0.79 |
| **A2 rerank** | 不必为可答性开启 rerank；只按排序收益与延迟权衡 |
| **A3 灰区 LLM** | 重点放在单 gold 情形：规则在那里误拒率 ~30% |
| **ROADMAP 演进路径** | 第一步的特征由"top1−top2 分差"改为"top1 相对背景分"，前者已证否 |

## 方法

### 样本

沿用 M1 的构造：每条 query 一对样本 —— 有答案（原始检索结果）与无答案
（剔除全部 gold 后的结果）。300 条 query 产出 300 + 299 个样本
（1 条 query 的 top-20 全是 gold，无法构造无答案样本）。

两种可见性：top-3（生产当前交给判断函数的条数）与 top-20（检索内部候选池）。
截取按检索排名先截前 k 条，再去掉无信号条目 —— 与生产看到的一致。

### 特征

- `top1`：最高分
- `gap12`：top1 − top2
- `gap_bg`：top1 − 其余分数的中位数

只用有相关性信号的条目。RRF 里纯 BM25 命中的 relevance 记为 0.0，是缺失
而非 0 分，不进入计算。

### 规则

| 规则 | 判可答条件 |
|---|---|
| R0 | `top1 ≥ a`（基线） |
| R1 | `top1 ≥ a` 且 `gap12 ≥ b` |
| R2 | `gap_bg ≥ c` |
| R3 | `top1 ≥ a` 且 `gap_bg ≥ c` |

### 选参与计分

- **按 qid 分组的 5 折交叉验证**：在 4 折上选参，在留出折上计分；同一 query
  的有答案与无答案样本在同一折，避免参数在配对样本上被调过
- 选参目标：误拒率 ≤ 10% 的前提下识别率最高（与 M1 同一约束）
- 候选阈值取特征的分位点（一维 101 个、二维 41×41），与分数尺度无关
- 置信区间：按 qid bootstrap 2000 次；与基线的差用**配对** bootstrap
- 留出折上的预测调用生产的 `rag.answerability.decide`；选参时的向量化判定
  与它的一致性由 `tests/test_answerability_eval.py` 的随机化测试守着

### "基线"有三个，别混

| 名称 | 含义 | rrf top-20 |
|---|---|---|
| M1 报告值 | 0.05 步长、有答案取 `relevances[0]` | 19.1% / 5.7% |
| 生产固定阈值 | `top1 ≥ 0.75`，生产口径（取最高分） | 19.1% / 3.0% |
| **R0 交叉验证** | 细网格单阈值，留出计分 | **58.9% / 10.0%** |

规则之间的比较一律以 **R0 交叉验证**为基线：选参预算相同，比较才公平。
拿新规则的交叉验证结果去比 M1 的 19.1%，会把"阈值调细了"算成"规则更好"。
